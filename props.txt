p_misaligned_blocks_dtlb_lookup: assert property (
  @(posedge clk_i) disable iff (!rst_ni)
  lsu_req_i && misaligned_ex_i.valid
  |->
  !dtlb_lu_access
);


// If LSU request is aligned, DTLB lookup follows request

  @(posedge clk_i) disable iff (!rst_ni)
  dtlb_lu_access == (lsu_req_i && !misaligned_ex_i.valid)
);

The bug we must catch in the old MMU is:

Same-cycle LSU DTLB PPN output bug

Signal:
  lsu_dtlb_ppn_o

Problem:
  For superpages, the old MMU puts virtual-address-derived bits into the wrong
  bit positions because it treats the PPN output like a physical-address bus.

Core mistake:
  physical address bits [20:12] correspond to PPN bits [8:0],
  not PPN bits [20:12].

So when we verify the old MMU, we must not only check:

Cycle N+1:
  lsu_paddr_o is correct

We must also check:

Cycle N:
  lsu_dtlb_hit_o is high
  lsu_dtlb_ppn_o is correct immediately

The scoreboard must include a property like:

// Same-cycle PPN must be correctly formed from PTE + VA superpage substitution.
p_lsu_dtlb_ppn_same_cycle_correct: assert property (
  @(posedge clk_i) disable iff (!rst_ni)
  lsu_req_i &&
  !misaligned_ex_i.valid &&
  (en_ld_st_translation_i || en_ld_st_g_translation_i) &&
  lsu_dtlb_hit_o
  |->
  lsu_dtlb_ppn_o == expected_lsu_dtlb_ppn
);
